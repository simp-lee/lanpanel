Create application

Choose a fixed upstream. New resources are saved stopped and unpublished. Every executable, working-directory, environment, write, and other filesystem path must be supplied by you. LanPanel does not install or edit application code; it also does not download, upload, or build it. It records the paths and manages the configured local process or ingress.

Complete the four setup steps below. The draft is saved only in this browser and is not sent to LanPanel until you choose Save. Do not enter secrets in this form.

Step 1 — Application identity

Choose whether this points to an existing local process or a fixed service on the Tailnet. The identity and lifecycle authority remain controlled by LanPanel.

Step 2 — Upstream and user-provided paths

For local_http, provide an already-installed executable and an existing working directory. LanPanel does not install or edit application code, install dependencies, or discover paths. All paths below come from you.

Remote process, shell, executable, working directory, and deployment controls are not available for tailnet_http.

Step 3 — Readiness checks

Readiness is evidence only: LanPanel will not change the application to make a check pass. Use a path and statuses that the configured upstream already serves.

Step 4 — Initial publication

Publication is saved as configuration only. It does not start the process or open ingress; publication performs fresh evidence checks later.
